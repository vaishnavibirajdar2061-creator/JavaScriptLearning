Workers
============
Interview Answer 
• Playwright workers are separate processes used to 
execute test files in parallel.  
• By default, Playwright automatically determines the 
worker count based primarily on the number of logical 
CPU cores available on the system, typically using about 
half of them.  
• This default can be overridden using the workers option 
in playwright.config.ts or the --workers command-line 
argument.  
• The optimal number of workers also depends on 
available RAM and the execution environment (local 
machine or CI/CD).

To Run playwright test
===========================
By deafult playwright exeutes every test case in headless mode(Without UI)

1. To run all test cases from all spec file(collection of test cases: suite)
    npx playwright test

2. To run specific test 
    npx playwright test tests/Tc001_FirstTest.spec.ts

3. To run tets with UI
    npx playwright test tests/Tc001_FirstTest.spec.ts --headed

4. To run test by customizing playwright worker
    npx playwright test tests/Tc001_FirstTest.spec.ts --headed --workers=1(sequentail executing)

5. To run Playwright test through playwright UI(dashboard)
    npx playwright test tests/Tc001_FirstTest.spec.ts --ui
    
6. To run test case on one browser
npx playwright test tests/Tc001_FirstTest.spec.ts --headed --project=webkit

Assertions
===================
-PW support inbuit assertions for validation of curent application state
-Assertions will help you to test actual result vs expected result

PW support two types of Assertion

1.Hard Assertion
-------------------
- If assertion fail then test will stop on that line not continue remaining execution
- hard assertion we implement in PW using expect()

2.Soft Assertion
--------------------
- If assertion fail then test will not stop excution you will see error and test continue remaining execution
- hard assertion we implement in PW using expect.soft()

Playwright provides autowait(30sec) for all actionable commands
---------------------------------------------------------------
Playwright performs a range of actionability checks on the elements before making actions to ensure these actions behave as expected. 
It auto-waits for all the relevant checks to pass and only then performs the requested action. 
If the required checks do not pass within the given timeout, action fails with the TimeoutError.

For example, for locator.fill(), Playwright will ensure that:
locator resolves to exactly one element
element is Visible
element is Stable, as in not animating or completed animation
element Receives Events, as in not obscured by other elements
element is Enabled
element is editable

Xpath Methods
===================
1.text()
-----------------
This method identify element based on visible text

-----------------
This method identify element based on visible text

----------------------------------

-------------

4.starts-with(): prefix match 
Syntax:
-------------

OR
//tagname[starts-with(text(),'partial text')]

To Run any Javascript command using Playwright we use evaluate()
Syntax:
----------
page.evaluate(()=>{
     javascript command
})

What evaluate() does
It executes the function you pass in the page’s context, not in Node.js.
This means it can access browser objects like:
document,window,localStorage

Why use evaluate()?
To read or modify the DOM
To run custom JavaScript inside the webpage
To get values not directly exposed by Playwright API
evaluate() is more flexible when accessing any page-level JavaScript.

shadow dom ele
--------------------
Shadow DOM:
Shadow DOM is a private/isolated DOM inside a web element, used to keep its HTML and CSS separate from the main page.

In simple words:
Shadow DOM = DOM inside a DOM, with isolation.

what is Shadow DOM?
----------------------
Whenever DOM is loaded inside another DOM is called Shadow DOM
Logic
----------
main document-->shadow host-->shadow root-->shadow ele

Which element we can called as shadow element?
----------------------------------------
if element is designed with #shadow-root(open) then that element is shadow ele

Parent tag/element for shadow element is shadow root
Parent tag/element for shadow root is shadow host

Shadow dom elements we can automate only using cssSelector

If element design with #shadow-root(closed) we can not automate this element
